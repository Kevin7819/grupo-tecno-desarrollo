# Feature: security-hardening — correcciones previas al merge de radio-v1

Objetivo: resolver los dos hallazgos bloqueantes (A1, A2) y los cuatro hallazgos medios (M1–M4) de la revisión independiente antes de integrar `feature/radio-v1` en `main`, con una prueba que demuestre cada corrección.
Rama: `feature/radio-v1` (HEAD `2d611f3`, árbol limpio al iniciar). Entrega: commits por unidad de trabajo, sin push. Runner: `C:\php84\php.exe artisan test` (PHPUnit 12, SQLite en memoria).

## Specs

- **S1 — A1, URL de recuperación confiable.** El enlace de restablecimiento debe usar una URL base de configuración (`APP_URL`), no la cabecera `Host` de la petición. En producción el enlace debe ser HTTPS; en local se permite HTTP para las pruebas. No se confía en cualquier host entrante, no se inventan dominios y se documenta el valor que debe proporcionar el despliegue, incluido el proxy inverso. Una `APP_URL` inválida o HTTP en producción debe fallar de forma explícita. Pruebas: petición con `Host` manipulado, inspección de la URL de la notificación con `Notification::fake()`, host ajeno ausente y esquema esperado. Sin correos reales.
- **S2 — A2, credenciales conocidas.** El seeder predeterminado no debe crear usuarios ni administradores autenticables con contraseñas públicas. La factory puede conservarse para pruebas, dejando claro que su contraseña no es de producción. Se corrige la documentación que afirma que no existe un seeder con contraseña conocida. Prueba: ejecutar el seeder en una base aislada y comprobar que no crea cuentas con credenciales predeterminadas; nunca contra la base local real.
- **S3 — M1, «Recordarme» administrativo.** Eliminar la opción del formulario administrativo y no solicitar persistencia desde el controlador. Mantener intacto el login/logout normal y el login de oyentes. Prueba: enviar `remember=1` y comprobar que no se habilita `remember_token` ni la cookie de persistencia.
- **S4 — M2, límite al cambiar la contraseña.** Añadir rate limiting a `profile.password` con el mecanismo existente, combinando identidad autenticada e IP para que cambiar de IP no eluda el límite. Sin registrar contraseñas ni datos sensibles. Ampliar las pruebas estructurales de seguridad y añadir pruebas de comportamiento; conservar CSRF. Revisar `PATCH /profile` sin añadir un límite arbitrario.
- **S5 — M3, invalidar otras sesiones.** Tras un cambio o restablecimiento exitoso de contraseña, las sesiones anteriores de la cuenta no deben seguir autorizadas. No se asume que `remember_token` alcance. Se verifica el driver de sesiones y se evita una dependencia innecesaria del mismo. La sesión actual puede seguir válida. Pruebas con dos sesiones independientes: una cambia/restablece la contraseña y la otra pierde acceso. Si se requiere un cambio operativo importante, se documenta y se pide decisión.
- **S6 — M4, esquema del stream y CSP.** En producción se rechazan las URLs de transmisión HTTP; se acepta HTTPS válido. Se conserva «Transmisión no configurada» cuando no hay URL válida y no se muestra «EN VIVO» ni un reproductor que la CSP bloqueará. La excepción HTTP se limita al entorno local y se documenta. Se rechazan otros esquemas y URLs malformadas. Pruebas: URL vacía, HTTPS válido, HTTP rechazado en producción, HTTP permitido en local y formatos admitidos.
- **S7 — Verificación final.** Suite completa, `pint --test`, `composer audit --locked`, `pnpm audit`, `pnpm run build`, revisión del diff completo, sin secretos ni cambios accidentales, `.env` fuera de Git, sin merge ni push. No se ocultan fallos ni se reducen pruebas para obtener verde.
- **S8 — Informe.** Resumen por hallazgo, archivos y motivo, pruebas nuevas, resultado real de cada comando, hallazgos abiertos, decisiones pendientes y estado de Git. No se afirma que los seis hallazgos están resueltos si alguno quedó solo documentado o pendiente de decisión.
